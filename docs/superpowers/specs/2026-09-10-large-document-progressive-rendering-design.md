# 大文档渐进渲染与交互性能设计

## 背景

当前 Markdown 阅读页已经支持顶层块索引、局部解析和内容更新时的 DOM 复用，但首次打开大文档时仍会一次性创建全部正文块、目录节点和标题观察器。测试用例中的 5 MB 文档包含约 2 万个标题、1800 个 Mermaid 块和 4000 个表格，这会在主线程集中触发 Markdown 解析、React 提交、目录布局和 Mermaid 调度，导致首屏卡顿、滚动掉帧。

本次调整的目标不是继续扩大解析缓存，而是让大文档在首屏阶段分阶段进入页面，同时减少目录和图表在不可见区域产生的工作。普通文档继续使用现有同步渲染路径，避免改变已经稳定的表格、锚点和目录体验。

## 目标与非目标

### 目标

- 大文档首屏优先显示标题和前若干可见正文块，避免一次渲染阻塞主线程。
- 后续正文在浏览器空闲帧或下一帧批量补齐，最终完整显示 Markdown 内容。
- 大目录默认只展开有限层级，标题进入目录视口附近时才建立激活观察关系。
- Mermaid 只在靠近阅读视口时进入渲染队列，并限制同时运行的任务数量。
- 文件局部刷新时，已完成渲染的未修改块继续复用；渐进渲染中的文档也能安全取消旧任务并应用新内容。
- 保留表格宽度、单元格选择、锚点跳转、目录定位、主题和 VS Code Webview 行为。
- 为首屏、补齐、局部刷新和取消任务增加自动化回归测试。

### 非目标

- 不重写 Markdown 解析器、表格选择模型或 Mermaid SVG 样式。
- 不改变普通文档的默认目录展开状态和正文布局。
- 不引入第三方虚拟列表依赖；首版使用已有 React、IntersectionObserver 和浏览器调度 API。
- 不承诺在一次渲染期间提前计算所有块的精确高度；占位区域只提供稳定的最小高度。

## 方案概述

### 1. 大文档判定

在 `MarkdownReadView` 建立块索引后，根据块数量、标题数量和 Mermaid 数量计算渲染策略。默认阈值如下：

- `blockCount >= 1200` 或
- `headingCount >= 500` 或
- `mermaidCount >= 80`

命中任一条件即进入大文档模式。阈值集中定义在性能模块中，测试可以覆盖边界，后续可调整而不改组件逻辑。

### 2. 正文渐进渲染

大文档模式把块按固定数量分成渲染批次，每批默认 80 个块：

1. 首批优先渲染，确保标题、第一屏正文和首个表格/图表尽快可见。
2. 尚未渲染的内容只保留轻量占位容器，并通过 `IntersectionObserver` 监听占位区；滚动接近占位区时才请求下一批。
3. 每次最多提交一个批次，并通过 `requestIdleCallback`（不支持时退回定时任务）让出主线程，避免滚动期间连续解析全部文档。
4. 初始 URL 锚点或目录点击命中未渲染标题时，使用导航批处理一次合并多个中间批次，减少深层跳转等待期间的调度和 React 提交次数。
5. 深层导航完成后只渲染目标附近窗口，前后使用估算高度占位；向上或向下滚动时再扩展窗口，避免把目标前的全部块一次性挂进 DOM。
6. 内容、来源上下文或刷新计划变化时取消旧调度，只保留最新内容的任务。

小文档继续沿用现有 `MarkdownReadView` 同步路径，不引入批次状态和占位布局变化。

### 3. 目录降载

`useTOC` 仍然一次提取标题元数据，但 `TableOfContents` 在大目录模式下使用渐进展示：

- 默认只渲染根级标题及每个根级标题下的第一层子标题。
- 其余子树保留在内存数据中，点击折叠三角或目录搜索/定位时按需展开。
- 大目录不再给所有正文标题建立 `IntersectionObserver`，只观察当前已渲染正文标题和前后有限窗口。
- 目录跳转到未渲染块时，先请求正文渲染到目标块，再执行定位和 2 秒高亮。

普通目录仍使用现有递归渲染路径，保证小文档视觉和交互完全不变。

### 4. Mermaid 调度

Mermaid 组件继续采用可视区域懒渲染，但把渲染入口统一到一个有界队列：

- 同时最多执行一个 Mermaid 渲染任务，保持现有 Mermaid 全局状态安全。
- 对已经取消、离开文档或内容已变化的任务，不再写回 React 状态。
- 视口外的 Mermaid 只保留占位，不触发 `parse` 和 `render`。
- Mermaid 错误仍按现有错误块显示，不影响其他批次。

## 数据流与取消策略

```text
markdown content
  -> indexMarkdownBlocks
  -> classifyRenderStrategy
  -> small document: existing synchronous model
  -> large document: progressive render controller
       -> first batch
       -> viewport placeholder observer
       -> one-batch idle queue
       -> visible Mermaid queue
       -> completed block map
```

渐进控制器使用版本号或 AbortController 风格的取消标识。每次内容变更都会递增版本号，旧批次在提交前检查版本号；不匹配时丢弃结果，不修改当前视图。这样可以避免连续保存文件时旧内容覆盖新内容。

## 表格、锚点和滚动保证

- 已经挂载的表格块不会因为后续批次补齐而重建。
- 表格身份同步仍在每次模型提交后执行，宽度恢复事件保持不变。
- 目录跳转先确保目标批次完成，再执行 `scrollIntoView`，避免跳到占位区域。
- 内容刷新前记录主滚动容器的 `scrollTop` 和可见锚点，批次提交后恢复；如果目标块被删除，则回退到最近的可见块。
- 表格横向滚动、目录左移和正文对齐逻辑不改变。

## 失败与降级

- 块边界不安全或标题元数据失效时，保留现有全量解析回退。
- 浏览器没有 `requestIdleCallback` 时使用 `requestAnimationFrame`。
- IntersectionObserver 不可用时，Mermaid 只渲染首批可见范围，避免一次启动全部图表。
- 批次调度出现异常时，显示已经完成的内容并记录开发环境性能标记，不让整个文档进入空白状态。

## 验收指标

- 1 MB、3 MB、5 MB fixture 首批标题和正文可见，页面不因首次解析长时间无响应。
- 大文档首次打开时，首个批次先提交，完整批次随后补齐。
- 修改单个普通段落时，未修改块 DOM 节点保持连接，滚动位置保持。
- 目录跳转到后续标题仍能定位，并显示 2 秒目标高亮。
- 视口外 Mermaid 不触发渲染；滚动到图表后才进入队列。
- 小文档现有单元测试、构建和表格/目录回归测试全部通过。
