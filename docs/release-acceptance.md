# 发布前验收清单

本文档用于 Feishu Markdown Viewer 的发布前验收。自动化门禁通过后，仍需在 Windows 原生 VS Code 中完成 GUI 验收；自动测试不能替代真实宿主环境检查。

## 自动化门禁

在仓库根目录执行：

```bash
TMPDIR=/tmp npm run verify:release
```

浏览器 E2E 需要先安装 Chromium，并在 Linux CI 使用 `xvfb-run`：

```bash
npm run test:e2e:install
TMPDIR=/tmp E2E_HEADLESS=0 npm run test:e2e -- --project=browser-extension
```

记录门禁输出、`playwright-report/`、`test-results/` 和构建产物路径。

## 安装与默认预览

1. 使用干净 VS Code Profile 安装 `.vsix`。
2. 双击打开 `.md` 和 `.markdown` 文件。
3. 确认默认编辑器是 **Feishu Markdown Preview**，页面进入只读阅读态。
4. 使用 **Reopen Editor With… → Text Editor** 可以回到原生编辑器。

预期：预览不会修改源文件；原生编辑器回退路径始终可用。

## 外部文件更新

1. 打开一个 Markdown 预览。
2. 在 VS Code 原生编辑器或外部编辑器中修改并保存。
3. 观察预览是否更新到新内容。
4. 切换其他编辑器标签再切回，确认内容不丢失、不回到顶部、不出现持续加载。

预期：内容更新只替换预览正文，切换标签不会无条件重载；失败时保留旧正文并显示可诊断状态。

## 主题与字号

1. 在阅读页切换浅色、深色和高对比主题。
2. 调整字号，检查正文、表格、代码块、引用和 Mermaid 同步变化。
3. 关闭并重新打开 VS Code，确认设置仍保留。

预期：页面背景、正文区域、表格滚动阴影和代码块颜色统一；深色主题下文字和连线保持可读。

## 目录与布局

1. 点击主标题、二级标题和三级标题目录项。
2. 确认标题定位准确，目录高亮跟随滚动。
3. 点击左上角按钮折叠/展开目录。
4. 打开宽表并横向滚动，确认目录自动收起不会改变正文居中布局；滚动离开表格后目录恢复。

预期：目录折叠不改变正文可读区域的对齐；标题层级、缩进和加粗状态稳定。

## 表格选择、复制与列宽

1. 点击一个单元格，确认单元格高亮。
2. 点击表格上边框选择整列，点击左边框选择整行。
3. 拖动选择范围到当前可视区外，确认表格自动横向滚动并扩展选择。
4. 框选单元格中的部分文字，确认可以复制文字而不被表格选区拦截。
5. 复制多单元格区域并粘贴到 Excel，确认表头识别为 HTML 表头、正文为表格数据。
6. 拖动列宽，切换标签或重新打开文件，确认列宽按文档和表格身份恢复。

预期：左移显示的列仍可通过顶部边框和单元格选择；原生滚动条无抖动，外框与表格宽度一致。

## Mermaid 正常图/错误图

1. 打开包含有效 Mermaid 的 Markdown，确认默认显示图表而不是源码。
2. 点击“预览”，确认弹窗中的图表居中。
3. 在图表视口上滚轮，确认滚动图表而不是正文；按 `Esc` 关闭弹窗。
4. 打开无效 Mermaid，确认显示错误降级状态且其他正文仍正常。
5. 在浅色、深色和高对比主题下重复检查。

预期：动态 Mermaid 资源全部加载，不出现 `Failed to fetch dynamically imported module`；错误图不阻塞整页。

## 源文件未被修改

验收前后执行：

```bash
git diff -- test-e2e.md
```

预期：只读预览、表格选择、复制和主题设置均不写回 Markdown 源文件。
